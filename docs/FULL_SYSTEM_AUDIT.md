## Critical Integration and Protection Map

- Entry: strategy registry/evaluators -> monitor/lifecycle -> account controls ->
  confirmation -> schedule, calendar, overnight, volatility, loss and exposure
  checks -> broker micro contract/quantity -> atomic job intent -> repeated
  send-boundary checks. Strategy Manager is shadow/research, not broker cutover.
- Exits: legacy watch lifecycle and adaptive stop calculations -> full-close
  request when signal closes/protection disappears/loss lock/emergency/schedule
  requires -> exact-account broker reconciliation. Original stop is attached at
  entry. Existing workers were neither restarted nor armed during implementation.
- Research: independent strategy backtest/paper remains distinct from portfolio
  simulation. New management adapters only attach to explicitly snapshotted new
  positions; old position policies are preserved. One completed episode includes
  all partial fills rather than inflating wins/trade count by exit leg.
- Data: trade ticks, quote timestamps, coverage windows and actual-contract
  histories remain separate. Missing/stale/as-of-unavailable history cannot
  qualify new entries/trailing. Rollover does not silently substitute a new
  contract for an old owned position.
- Runtime/launchers: CMD starts the local interface menu, not an account.
  Interface restart preserves workers. Explicit guarded worker controls retain
  reconciliation requirements. `scripts/practice_smoke_test.py` can send orders
  if deliberately run and was not used.
- UI/API: loopback host/session/CSRF boundaries remain. Research policy writes
  separate tables, never credentials/funded controls. Practice/Leader share
  feature visibility without sharing arming or broker restrictions.
- Attribution: actual broker fill matching stays conservative and separate from
  watch marks and paper results. No measured excursion is invented for existing
  broker positions lacking an observation history.

## Verification and Remaining Risks

The original manager suite exercised arbitration, global/group risk, reservations,
concurrency/contention, restart/uncertain/partial outcomes, causal research and
settings isolation. New exit tests cover monotonic protection, policy freezing,
duplicate/partial fills, exact quantities, wrong contracts/stale observations,
same-entry-signal comparisons, costs, excursion/giveback and new/legacy adapters.
Full regression: 433 tests, no failures, errors or skips. TypeScript/Vite and compileall pass. New Trade Management and existing Manager/Control Center browser checks pass in both profiles at six sizes; Streamlit rendering is tested in both profiles. Browser checks use temporary SQLite and blocked broker clients, not funded data. See TRADE_MANAGEMENT_ENGINE.md for exact commands, the interrupted sandbox-only supplemental run, and remaining dependency warnings.

Potential improvements are not recorded as confirmed defects: shorter exit
timeframes, selecting a more profitable target, changing overnight strictness,
confidence-based sizing, correlation hedges or selecting a backtest winner.
No genuine strategy history was available to demonstrate performance. Some
legacy dependencies are unpinned; dependency hardening needs a separately tested
upgrade. Large paper audit arrays and synchronous historical comparison need
measured retention/scheduling work before large-scale deployment.

Official ProjectX references establish request schemas, not proof that linked OCO
orders resize safely after a partial exit. No account mode was changed. Stop/TP
amendments and partial broker sends remain blocked; unknown outcomes must not be
retried blindly. Full transport validation, exchange-open feed tests, measured
line/branch coverage and out-of-sample performance remain explicit follow-ups.
